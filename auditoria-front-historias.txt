HU-01 · Usar vivos, moderación y consola con una cuenta real
Prioridad: P0
Como creador o moderador que inició sesión contra Serverpod,
quiero poder comentar en un vivo, iniciar mi vivo, programar un show,
moderar y abrir la consola,
para poder hacer el recorrido del hackathon con cuentas reales.

Problema actual:
  - Con AUTH_SOURCE=serverpod nadie llama a MockPlatform.bindSession;
    sólo lo hace el repositorio mock (mock_auth_repository.dart:27).
  - Toda acción que necesita actor lanza ForbiddenFailure
    (core/mock/mock_platform.dart:621-624).
  - El usuario ve "Tu cuenta no tiene permiso para hacer esto" o
    "El servidor rechazó la solicitud" (moderation report_queue.dart:68).
    El mensaje es falso: quien rechaza es el mock.
  - Como el vivo no se puede iniciar, el host nunca entra al canal de
    Agora: no hay video con cuentas reales.
  - Un admin real ve "Acceso restringido" en la consola
    (admin_console_page.dart:125-131).

Criterios de aceptación:
  [ ] Con AUTH_SOURCE=serverpod se puede programar → iniciar → invitar
      → ocultar un comentario → terminar → replay.
  [ ] Ningún mensaje de error dice "el servidor" cuando falla el mock.
  [ ] El host publica video en Agora con una cuenta del seed.

Nota: el arreglo definitivo es M4 (live) y M6 (admin) en el backend. Ver
la épica C.

HU-03 · Ver por qué falló mi inicio de sesión

para saber qué corregir.

Problema actual:

    (features/auth/data/repositories/serverpod_auth_repository.dart:204-227).
  - El cliente (serverpod_auth_idp_client 4.0.3) lanza

  [ ] El mapeo usa `is EmailAccountLoginException` y su `reason`, con
      los equivalentes de registro y reset.
  [ ] Contraseña incorrecta muestra la copy de credenciales inválidas.
  [ ] Hay un test por cada motivo.
